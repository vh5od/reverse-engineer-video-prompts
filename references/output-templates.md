## 1. 默认最终格式

用户要求反推、生成或优化 Prompt，且没有明确指定其他格式时，必须使用以下结构。不要改名、翻译、删除或新增顶层字段。

先输出语义资产定义块。只定义本次任务实际使用的资产，并使用以下句式：

```text
将 [用户上传商品图] 定义为 【主商品】。【主商品】只继承上传图片中商品的整体轮廓、长宽高比例、主辅色、材质、原始结构、部件数量与相对位置、标签位置、正面方向和核心识别特征，不继承原图背景、手部、支撑物、光影或构图；默认将【主商品】视为不可变形刚体，只允许等比例整体缩放、整体平移和整体旋转。

将 [用户上传模特图] 定义为 【主角】。【主角】只继承上传图片中的面部五官、年龄、肤色、体型比例、发型和人物身份，不继承原图服装、姿势、动作、表情、背景或光线；跨镜头始终保持同一个人。

将 [用户上传服装图] 定义为 【参考服装】。【参考服装】只提供服装的品类、版型、长度、层次、颜色、材质、图案、配件和可见标识；如果图片中存在模特，不继承该模特的脸、身体、姿势或发型。
```

没有模特图或服装图时删除对应定义，不要保留无用资产。需要场景、道具或其他资产时，沿用相同结构：先说明继承什么，再说明不继承什么。资产定义完成后，正文只使用 `【主商品】`、`【主角】`、`【参考服装】` 等语义名称。

再输出：

```json
{
  "视频风格": {
    "核心方向": "",
    "节奏": "",
    "视觉质感": "",
    "整体调性": "",
    "环境": "",
    "灯光": "",
    "色彩逻辑": "",
    "镜头要求": "",
    "产品规则": ""
  },
  "视频内容": {
    "故事": ""
  },
  "分镜结构": [
    {
      "镜头": "Shot 01",
      "时间": "",
      "标题": "",
      "机位": "",
      "构图": "",
      "画面": "",
      "镜头运动": "",
      "转场": ""
    }
  ],
  "关键约束": {
    "核心逻辑": "",
    "最重要要求": "",
    "禁止项": ""
  }
}
```

没有实际参考图时仍保留 `[用户上传商品图]` 等描述性占位符。不得使用 `@image1`、`image1`、`image2` 等序号引用。用户给出其他语义角色名时使用用户名称，不改变其余结构。

根据视频证据增减 `分镜结构` 中的 Shot。每个 Shot 必须保留全部八个字段。

## 2. 字段职责

- **视频风格**：回答“这支视频如何被拍出来”。
- **视频内容**：用一句完整因果链回答“这个世界里发生了什么”。
- **分镜结构**：按真实时间顺序回答“观众看到什么”。
- **关键约束**：只保留会破坏核心机制、时间逻辑或商品一致性的高风险问题。

字段内容应满足：

- `核心方向` 只保留一个主导视觉方向；
- `灯光` 说明主光方向、照亮对象、暗部和环境光；
- `色彩逻辑` 区分环境色、商品色和特效色来源；
- `镜头要求` 说明空间连续性、运动中心和 Reveal 时机；
- `产品规则` 集中写明不可变身份、允许的变换预算和接触策略，不在每个 Shot 重复；
- `画面` 使用具体动作和可见中间态；
- `转场` 写明切、遮挡、主体掠过或连续镜头，不虚构转场。

涉及参考资产时还应满足：

- `视频内容.故事` 不得给资产分配参考图不支持的功能身份；
- `画面` 中的动作必须能在允许的变换预算内完成；
- 人物互动和环境接触不得暗示不存在的承载面、入口、空腔、底座、推进或连接结构；
- 物理真实性与资产身份冲突时，优先保持资产身份，通过刚体运动、外力、环境反馈或摄影机运动建立可信感；
- `禁止项` 只保留删除正向冲突后仍存在的高风险漂移，不堆叠同义禁词。

## 3. Analysis 模式

只有用户明确要求分析、审查或校准时，才可只输出：

```markdown
### 反推结论

- 核心效果：
- 一句话事件链：
- Hook：
- 特效机制：
- 镜头结构：
- 效果定义元素：
- 可替换变量：

### 证据与置信度

- 已观察：
- 合理推断：
- 未确认：
```

用户同时要求 Prompt 时，Analysis 只能作为简短前置内容，不能替代默认最终格式。

## 4. 自然语言模式

只有用户明确要求“纯文本 Prompt”“自然语言 Prompt”或目标系统拒绝 JSON 时，才将默认结构压缩为连续文本。保持：

- `[用户上传…图]` 到 `【语义角色名】` 的资产绑定；
- Beginning → Development → Transformation → Reveal/Final；
- 动作因果和中间态；
- 商品一致性；
- 少量高风险约束。

不要自行把自然语言模式设为默认。

## 5. JSON 检查

- 使用双引号；
- 不写注释；
- 不使用尾随逗号；
- 不在 JSON 内使用未转义的换行；
- 保证能被 JSON 解析器直接读取；
- 顶层字段必须且只能是 `视频风格`、`视频内容`、`分镜结构`、`关键约束`；
- 每个 Shot 必须包含八个固定字段；
- JSON 代码块之外只允许出现语义资产定义块和必要的简短分析；
- 资产定义后，JSON 正文只使用 `【语义角色名】`，不得出现 `@image1`、`image1`、`image2` 等序号引用。
