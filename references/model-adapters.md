# 模型表达适配

目标模型的参数和能力会变化。优先遵守用户提供的官方说明或界面字段，不要凭记忆编造专属参数。

## 1. 先识别输入方式

判断目标工具属于哪一种：

- 单一自然语言 Prompt；
- 分镜或时间轴输入；
- 首尾帧控制；
- 多参考资产绑定；
- 视频到视频或效果迁移；
- Prompt 与独立负面提示词字段。

不知道目标模型时，输出通用的时间顺序 Prompt，不附加平台专属参数。

## 2. 单一 Prompt

保留：

- 第一帧；
- 主体和空间关系；
- 连续动作因果；
- 可见中间态；
- 最终状态；
- 主导风格与摄影机；
- 少量高风险约束。

将重复的全局规则只写一次。不要把每个 Shot 写成互相独立的世界。

## 3. 分镜或时间轴

把 Shot 映射到真实时间段。每段只承担一个主要功能，并明确承接上一段的主体、位置和运动方向。

如果系统会把每段独立生成，应重复最少量的连续性锚点：

- 同一主体；
- 同一环境；
- 前一段结束位置；
- 运动方向；
- 光线方向。

不要重复完整风格段落。

## 4. 首尾帧控制

首帧负责：

- 锁定场景、构图和初始主体；
- 避免提前出现最终 Reveal；
- 为进入方向预留空间。

尾帧负责：

- 锁定最终主体、朝向和尺度；
- 保证商品或角色可识别；
- 保证摄影机已经停稳。

Prompt 重点描述首尾帧之间可见的动作路径，不要重复描述两张图中已经明确的静态信息。

## 5. 参考资产绑定

默认使用语义资产绑定，不在 Prompt 正文直接使用界面的序号引用。先建立映射：

```text
将 [用户上传商品图] 定义为 【主商品】。
将 [用户上传模特图] 定义为 【主角】。
将 [用户上传服装图] 定义为 【参考服装】。
```

定义完成后，正文只使用 `【主商品】`、`【主角】`、`【参考服装】` 等语义名称。即使平台界面内部显示 image1、image2 或类似编号，也不要把这些编号写进自然语言 Prompt。只有用户明确要求输出某个平台的原生绑定语法时，才在平台参数层提供映射，同时保持 Prompt 正文的语义名称不变。

## 6. 负面提示词

存在独立负面字段时，将高风险禁止项移入该字段。不存在时，把关键要求改写为正面结果。

优先：

> 商品在风暴收束后第一次完整出现。

少用：

> 不要提前出现商品，不要提前显示包装，不要开场看到产品。

## 7. 信息密度

- 短视频：强调时间节奏、动作动词和转化中间态；
- 长视频：先建立段落级事件结构，再细化镜头；
- 参考图强控制：减少重复外观形容，增加动作和空间信息；
- 纯文本生成：补充主体外观，但不要让装饰细节压过事件机制。
