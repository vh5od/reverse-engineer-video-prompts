# 视频效果分析框架

复杂视频或商品 Reveal 任务按本框架分析。不要逐帧复述；只保留能解释事件机制的证据。

## 1. 证据分级

每项结论标记为：

- **已观察**：在视频或多个关键帧中直接可见。
- **合理推断**：最符合连续画面的解释，但不能直接证明。
- **未确认**：采样不足、遮挡、压缩或运动模糊导致无法判断。

对方向、速度、因果和隐藏切镜保持谨慎。单帧只能证明状态，不能证明运动过程。

## 2. 一句话事件链

使用：

> 主体 A 做什么 → 导致 B → B 形成中间态 C → C 收束或转化为 D。

避免：

> A 在运动，同时 B 出现，然后出现 D。

后者只有并列事件，没有因果。

## 3. Hook

单独分析前 0–2 秒：

- 什么首先抓住注意力；
- 主体从哪里、以何速度进入；
- 摄影机是否已经运动；
- Hook 建立了危险、悬念、尺度还是反常感；
- 最终结果是否应当保持隐藏。

## 4. State 与 Transition

分别记录：

- Beginning State；
- Transition 1；
- Intermediate State；
- Transition 2；
- Final State。

转化必须包含可见中间态。例如：

> 多个实体向中心汇聚 → 加速环绕 → 个体轮廓被环境反馈和运动残影遮挡 → 形成连续动态体 → 动态体收束 → 最终主体显形。

不要直接写“多个实体变成商品”。

## 5. 因果与视觉证据

为每个特效回答：

1. 谁发起动作；
2. 动作作用于什么；
3. 环境产生什么反馈；
4. 反馈如何增强；
5. 个体何时变得不可辨认；
6. 最终状态如何从中间态产生。

不可能事件也要有可信视觉证据，例如遮挡、惯性、阴影、反射、沙尘、水花、碎屑、体积光或表面形变。

## 6. Shot 划分

按叙事功能而非固定数量划分：

- **Hook**：建立异常和运动主体；
- **Core Event**：发展互动、因果与转化；
- **Reveal/Payoff**：解决悬念并建立最终 Hero State。

每个 Shot 记录：

```text
时间：
功能：
机位：
构图：
主体动作：
环境反馈：
镜头运动：
连续方式：
```

判断运动属于主体还是摄影机。明确摄影机跟随谁、向哪里移动，以及是否保持事件中心稳定可读。

## 7. 固定元素与变量

Effect-defining 通常包括：

- 进入方式与方向；
- 主体数量关系；
- 汇聚、碰撞或交互机制；
- 核心中间态；
- Reveal 或最终状态的形成方式。

Incidental 通常包括：

- 具体颜色；
- 地点与天气；
- 品牌与商品；
- 道具数量；
- 背景人物和装饰。

颜色按来源描述：环境色由场景决定，主体色来自参考资产，特效色由主体色或事件物质推导。

## 8. 资产身份图谱与变换预算

只有存在参考资产时才提取：

```text
类型、轮廓、比例、主辅色、材质、结构、正面方向、
部件拓扑、部件数量与相对位置、标签或面部位置、
核心识别特征、易变形部分
```

把结果整理为：

```text
不可变身份：必须跨 Shot 保持的轮廓、比例、拓扑、部件和识别特征
允许的变换：默认仅为等比例缩放、整体平移、整体旋转、光影与反射变化
禁止的结构变化：拉伸、压扁、流线化、开孔、融合、拆分、增删或重排部件
```

把资产理解为由部件及其空间关系组成的身份图谱，而不是一组颜色关键词。保留颜色和面部、却改变身体轮廓或部件关系，仍然属于身份漂移。

将一致性规则集中写一次，不要在每个 Shot 重复。禁止新增标识或无法由参考图确认的文字。只有用户明确要求结构转化时才扩大变换预算。

## 9. 机制兼容性门控

在把参考视频机制迁移到新资产前，建立以下检查表：

```text
原机制所需结构：平面、空腔、关节、承重区、接触区、前后方向等
替换资产已有结构：可由参考图确认的真实结构
功能角色：资产是否被要求成为载具、平台、容器、服装、建筑或生物
物理补全压力：是否需要模型发明支撑、推进、浮力、连接、承重或流线结构
身份代价：完成动作是否会改变不可变身份
```

判断原则：

- 机制兼容：资产现有结构足以完成动作，且不超出变换预算；
- 条件兼容：保留叙事功能，但需要把动作改为刚体运动、外力驱动、环境响应或摄影机运动；
- 不兼容：机制的成立依赖重塑资产，必须删除该机制，只保留更高层的 Hook、悬念、尺度、Reveal 或镜头逻辑。

不要把“商品可以出现在某环境中”误写成“商品承担该环境中常见物体的功能”。环境关系不等于功能身份。

## 10. 冲突修复

依次检查：

- **时间冲突**：结果需要最终 Reveal，但开场已完整出现；
- **主体冲突**：不同段落指定了不同事件发起者；
- **镜头冲突**：要求一镜到底，同时使用无过渡的不同机位；
- **风格冲突**：多个视觉类型争夺主导地位；
- **颜色冲突**：特效既固定颜色又要求继承参考图；
- **结构冲突**：刚性主体被要求像液体一样变形；
- **功能冲突**：资产被赋予参考图不支持的承载、容纳、穿戴、推进或变形功能；
- **物理冲突**：真实浮力、承重、空气动力或水动力要求迫使模型补造结构；
- **交互冲突**：人物站立、进入、乘坐或操作资产，暗示参考图中不存在的平台、入口或控制结构；
- **语义簇冲突**：多个看似中性的词组合后形成载具、建筑、生物等完整先验。

删除或重写冲突源，不要只追加“禁止这样做”。

修复顺序：

1. 删除错误的功能角色；
2. 将主体运动降级为完整资产的刚体运动，或改由摄影机、环境与外力提供动感；
3. 降低会迫使结构补全的物理真实性；
4. 移除要求人物使用不存在结构的交互；
5. 最后才保留少量、高风险、可验证的负面约束。
